### 3.2 实验目标与总体流程

本节需要用自己的话说明完整流程：

1. 用户上传短视频，网站立即显示可播放视频卡片。
2. 服务端写入 `processing` 状态和 SQLite `jobs` 本地耐久队列。
3. 本地 worker 异步领取任务，进行关键帧抽样、视频理解、审核和打标签。
4. 默认通过 Ollama 调用本地 Qwen3-VL 4B，多模型候选可在后台选择。
5. 审核结果写入 SQLite 元数据和事件日志，前端轮询更新摘要、标签和状态。
6. 可选使用 Kafka 连接前三章的流处理架构，把视频进入事件和审核结果从本地队列扩展为消息队列。

本节要回答“为什么这样设计”：学生电脑需要稳定跑通，所以默认使用本地轻量架构；工业系统通常会把 SQLite jobs 替换为 Kafka/Pulsar，把本地媒体目录替换为 MinIO/S3，把 SQLite 元数据替换为 PostgreSQL/ClickHouse/湖仓表，把 Ollama 替换为独立模型服务或推理集群。

### 3.4 上传可见与异步处理验证

本节是本实验的核心验收点。必须证明视频上传后先显示出来，随后才异步完成理解和打标签。

报告中必须包含：

1. 自选视频文件名含学号，例如 `upload_2021001234_campus.mp4`。
2. 上传标题含学号，例如 `2021001234_自选上传_校园运动`。
3. 上传后网站立即出现视频卡片，视频区域是真实播放器，摘要和标签区域可以显示 loading 占位。
4. `/api/videos` 中该视频初始状态为 `processing`，`metrics.model.backend` 初始为 `pending`。
5. `/api/health` 中 `jobs.queued` 或 `jobs.running` 大于 0。
6. `/api/events` 中出现 `ingest`、`queued`、`worker`、`understanding`、`moderation`、`publish` 等阶段。
7. 处理完成后，状态变为 `published`、`review` 或 `rejected`，摘要、标签、风险分数和原因完整显示。

macOS / Linux 上传命令示例：

```bash
cp data/incoming/campus_sports.mp4 "data/incoming/upload_${STUDENT_ID}_campus.mp4"
curl -F "title=${STUDENT_ID}_自选上传_校园运动" \
  -F "video=@data/incoming/upload_${STUDENT_ID}_campus.mp4;type=video/mp4" \
  http://127.0.0.1:5050/api/upload
curl http://127.0.0.1:5050/api/videos
curl http://127.0.0.1:5050/api/events
curl http://127.0.0.1:5050/api/health
```

### 3.7 与流批一体架构的关系

本实验默认不强制启动 Kafka、Flink、MinIO 或 Paimon，是为了保证普通学生电脑能在课堂内跑通完整业务闭环。但报告必须解释它和前三章流批一体架构的对应关系：

| 本实验教学默认 | 工业界常见替换 | 需要说明的问题 |
| --- | --- | --- |
| SQLite `jobs` 表 | Kafka / Pulsar / RabbitMQ | 为什么上传服务与审核 worker 要解耦 |
| SQLite `events` 表 | Kafka 日志、ClickHouse、OpenSearch | 为什么需要可观测事件 |
| `data/media` 本地目录 | MinIO / S3 / 对象存储 | 为什么媒体文件不适合直接放入数据库 |
| 本地 worker | 容器化消费者、Kubernetes Job、Ray worker | 为什么模型推理应独立扩缩容 |
| Ollama 本地模型 | vLLM / SGLang / Triton / 云模型服务 | 为什么模型服务要有明确接口和超时 |
| `/api/videos` 查询 | Serving API、湖仓分析、实时看板 | 为什么结果既要服务前端，也要支持后续分析 |

如果完成 Kafka 扩展，请给出含学号的 topic、生产者输出、消费者输出和处理结果。Kafka 扩展是加分项，不是基础合格的必要条件。

| 审核策略增强 | 1 | 增加 OCR/ASR、敏感词、闪烁风险、低质画面等扩展分析，并解释局限 |

## 七、学术诚信与安全注意事项

1. 自选短视频应来自本人拍摄、开源素材或课程允许的公开测试素材，不要使用含他人隐私、肖像争议、未授权商业内容的视频。
2. 不要上传暴力、色情、赌博、隐私泄露等真实违规素材。需要测试审核时，使用课程内置样本或合成样本。
3. 不要提交 Ollama 权重文件、系统账号信息、浏览器 Cookie、SSH key、API key 或任何个人敏感数据。
4. 如果使用互联网下载测试视频，报告中必须写明来源和使用理由。
5. 报告中的截图、日志、API 返回结果应来自本人本机运行，不能只修改文字说明冒充实验结果。
